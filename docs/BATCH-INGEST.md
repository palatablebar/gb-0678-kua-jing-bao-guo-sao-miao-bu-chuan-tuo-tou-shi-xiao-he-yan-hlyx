# 同日扫描重传采信协议

同一业务日的扫描可能拆成多个文件送达，重传时既可能是补片（只含差量），也可能覆盖整批。本协议裁决重传性质、维护**唯一扫描全集（canonical snapshot）**，路径裁决（M4）与时效计算（M5）只读取该全集，不再直接读单文件。

## 1. 文件指令

指令行以 `#` 开头，只允许出现在文件首部、任何数据行之前，一行一条：

| 指令 | 含义 | 约束 |
|---|---|---|
| `#mode=full` | 整批覆盖：本文件代表该业务日的完整扫描全集，采信后整体替换旧全集 | 与 `patch` 二选一 |
| `#mode=patch` | 补片：只含差量与撤回，在旧全集上增删 | 与 `full` 二选一 |
| `#date=YYYY-MM-DD` | 业务日 | 格式非法按 `BAD_DIRECTIVE` 拒绝 |
| `#withdraw=<scan_id>` | 撤回全集中的既有扫描 | 可重复；空值拒绝 |

未知指令、缺等号、非法 mode 一律 `BAD_DIRECTIVE`（422），文件整体不采信。

## 2. 重传性质识别

1. **显式声明优先**：含 `#mode` 时按声明裁决，台账记 `mode_basis=declared`。
2. **无声明时推断**，记 `mode_basis=inferred`：
   - 文件含任意 `#withdraw` 指令 → 推断为**补片**（整批不需要撤回指令，缺即自然退出）；
   - 文件内 scan_id 集合覆盖当前全集的全部扫描 → 推断为**整批覆盖**；
   - 当前没有任何全集（首个文件）→ 推断为整批；
   - 其余情形线索冲突，抛 `AMBIGUOUS_MODE` 拒绝猜测，要求上游补 `#mode`。

## 3. 唯一扫描全集与三类判定

全集以 `scan_id` 为唯一键，跨文件合并：

- **新扫描（new）**：scan_id 首次进入全集。整批模式下指该文件带来、旧全集不存在的扫描。
- **重复扫描（duplicate）**：scan_id 已在全集且整行内容逐格一致，计重复、不新增、不重复核算。
- **冲突（conflict）**：scan_id 已在全集但内容不同，保留全集原值，新行隔离为 `CANONICAL_CONFLICT`，绝不后写覆盖。
- **撤回扫描（withdrawn）**：
  - 补片模式：`#withdraw` 命中即从全集删除；
  - 整批模式：旧全集中未在新文件出现的 scan_id 统一记撤回；
  - 撤回目标在全集不存在 → `WITHDRAW_UNKNOWN` 隔离并计数，不静默成功。

补片只做差量增删，先前扫描原样保留，因此不会“把补片当整批丢掉先前扫描”；整批一次性替换，因此不会“一律累加留下已撤回记录”。

## 4. 原子切换与幂等

- 多文件按提交顺序在内存完成全部解析与全集裁决；**任一文件失败（编码、表头、空态、指令、歧义）整体中止，数据库不写入，上一可用全集继续提供服务**。
- 全部成功后，在单个 SQLite 事务内写入 `snapshots` 与 `batch_files` 台账并一次性切换。
- 每个文件按 sha256 去重：
  - 同一提交内出现完全相同文件 → `DUP_FILE` 拒绝；
  - 文件 sha256 命中历史台账 → 标记 `replayed` 跳过裁决，**同一补片重试不新增任何扫描**；
  - 文件集合指纹一致时复用既有快照，不产生新批次、新 run。

## 5. 接口

- `POST /api/batches`：`multipart/form-data` 重复字段 `files`，或 JSON `{"csv_files": [...], "parameters": {...}}`。成功返回在新全集上重跑 M2–M7 的完整 run；失败返回 422 且全集不变。
- `GET /api/batches`：快照台账与当前全集。
- 单文件预览 `/api/scans` 与 `/api/runs` 的既有行为不变，供无重传场景使用。

## 6. 溯源

每条全集行带两类血缘：`_origin` 记录物理来源 `[文件序号, 物理行号]`（序列化为 `F1:L12`），用于页面展示与人工复核；`_sources` 使用稳定的 `scan_id` 贯穿 M2–M7 的血缘去重、M6 平衡核对与 M7 封存，因此重传后文件序号变化不影响复核算。隔离行（冲突、撤回未命中）以 `Q:` 前缀区分，不会与采纳行血缘重叠。
